Part I

The idea

A research instrument for a thin seam, where the configuration space is the research surface.

What it is

AXIOM is a research instrument, not a product. Its job is to express any cellular automaton, swarm, or graph-dynamical system as a configuration, run it, and observe it with a full analysis suite.

It is written in Rust and runs on the CPU by default, with an optional GPU path. An experiment is a config file plus a seed, so it reproduces exactly. The engine itself is a thin driver: it reads the config and wires the chosen modules together.

AnalogyA modular synth for artificial life›

Think of a modular synthesizer. The sound is not baked in; you patch oscillators, filters, and envelopes together, and the patch is the instrument. AXIOM patches together a substrate, a rule, a nonlinearity, an integrator, and a set of observers. The patch is a text file. Change one cable and you have a different experiment, not a different program.

FullThin driver over trait objects›

Around 3,600 lines of Rust across 20 modules, zero warnings across feature combinations. engine.rs matches on the tagged config enums and instantiates trait objects (Rule, Observer, and the substrate types), then steps with ping-pong buffers. Every run is tagged with an FNV-1a provenance hash over its serialized config.

The seam it is built for

The edge AXIOM targets is the intersection of graphs, cellular automata or swarms, and machine learning. Those three communities rarely share a codebase. Treating them as one configurable substrate turns combinations that are normally separate projects into one config change.

A learned rule on a hypergraph, PageRank as an observable over an evolving swarm, a spacetime-relaxed world model: each is a config here, not a rewrite.

A grid is a graph with lattice adjacency; a swarm is a graph with proximity edges; a hypergraph generalizes edges to n-ary relations. One abstraction, four realizations.
FullRules as message passing›

A convolutional CA update and a graph message-passing step are the same operation, aggregate(neighbors) → update, on different neighborhoods (a fixed lattice versus learned edges). The grid Lenia path is specialized and rayon-parallel for speed; a generic mp_step runs the same law over any Substrate. The concept is shared; the hot loop is not over-abstracted.

Everything is a config

One serde tree mirrors the whole parameter taxonomy. Each field selects and parameterizes a module. Invalid combinations fail at load with a reason, not silently at runtime.

rule:
  type: lenia
  dt: 0.1
  kernels:
    - { radius: 13, core: gauss_ring, beta: [1.0],
        growth: { kind: gauss, mu: 0.15, sigma: 0.015 } }
AnalogyA recipe card, not a kitchen rebuild›

Most simulators make you edit the kitchen to change the dish. Here you edit the recipe card. The card is validated before anyone starts cooking, so "gray-scott needs exactly two channels" or "kernel radius too large for this grid" is caught at the door.

Part II

The engine

One update loop, a small set of swappable modules, and a seam that puts grids and graphs on the same footing.

The update loop

State lives in a flat multi-channel field. A rule reads the current field and writes a scratch field; the two are swapped. Observers run over the live state on demand. That is the whole cycle, repeated.

Five rules, one trait

A second, structurally different rule dropping into the same trait with no engine change is the proof the abstraction holds. Classic scalar Lenia is the one-kernel, one-channel case of the general multi-kernel form.

FullFlow Lenia and the NCA›

Flow Lenia advects mass along flow·∇U − concentration·∇A using reintegration tracking (bilinear splat, displacement clamped below one cell), so total mass is conserved by construction. The NCA rule is a per-cell MLP over a four-filter perception (identity, Sobel-x, Sobel-y, Laplacian) per channel; the Laplacian is what lets one 3×3 step represent a diffusion rule.

Four substrates, one abstraction

The same growth law that drives a grid runs over a small-world graph and a hypergraph, each one config apart. PageRank is a first-class observer over any of them, including the emergent interaction graph of detected organisms.

Part III

Measurement & learning

Most CA tools render. Few measure. The analysis layer, learned rules, discovery, and inference across time are where the instrument earns its name.

The analysis layer

Observers run over the live state and emit named metrics: mass and centroid, connected-component detection with per-organism geometry, and PageRank centrality over the interaction graph the organisms form. Every run writes a metrics log.

This is the differentiator. Many tools render a cellular automaton; almost none expose graph, detection, and dynamical descriptors over the same live state.

Learning a rule

A neural cellular automaton, where the rule is a small network, is fit to imitate a Gray-Scott step. The default trainer is gradient descent with hand-derived backprop and Adam; evolution strategies are the gradient-free alternative. The loss drops cleanly, and the learned rule is then evaluated as a world model: prediction error against the true simulator as a function of how far ahead it rolls.

FullAnalytic backprop + rollout error›

The gradient of the one-step MSE is derived by hand through the residual update, the second linear layer, the relu, and the first layer, accumulated over cells and optimized with Adam. No autodiff backend is needed for a 2-layer MLP. Evolution strategies (antithetic finite difference) remain available. rollout_error then rolls the learned rule and the true rule from the same seed and reports per-step MSE, which grows with horizon in the way a forward world model does.

Illuminating the space

Instead of searching for one best rule, MAP-Elites keeps the most structured pattern found in each region of behavior space. The result is a map of the diverse behaviors Lenia can produce, rendered as a montage over that space: rings, labyrinths, spots, and sparse gliders side by side.

AnalogyA field guide, not a trophy›

Ordinary optimization brings back one winner. Quality-diversity brings back a field guide: one strong specimen per niche, organized so you can see the whole range at a glance. Here the niches are binned by how much mass survives and how much it moves.

Inference across time

Standard simulation steps forward and accumulates error. The spacetime-loaf mode instead treats the whole space-by-time volume as one field and relaxes it to global consistency. Fix the first and last frames, relax, and the occluded middle comes back.

→ 0
interior reconstruction error after relaxation
~1400×
closer to the true trajectory than the occluded guess
FullA convex energy over the volume›

The mode minimizes E = Σ ‖V[t+1] − F(V[t])‖² over the volume with the endpoints fixed, where F is one reaction-diffusion step. For a linear F the energy is convex, so gradient descent recovers the true interior exactly. Information flows backward and sideways in time, so there is no rollout-error accumulation. A nonlinear Fisher-KPP F is also supported, using the analytic vector-Jacobian product; the energy is then non-convex, relaxation still descends and recovers most of the interior, but convergence is not guaranteed.

Part IV

Performance

The CPU path is the reference the rest is checked against. The GPU path is the speed, kept honest by that reference.

CPU oracle, GPU speed

The Lenia convolution runs as a headless GPU compute pipeline, validated to match the CPU result to floating-point precision, and is the default execution path for eligible single-kernel Lenia. Each workgroup caches its cell block plus halo in shared memory and convolves out of that tile, which collapses the redundant global reads a direct gather makes.

Honest finding

Even tiled, the GPU is memory-bound and the rayon CPU path is genuinely competitive: ~7× at 512², not orders of magnitude. Multi-kernel / multi-channel GPU and FFT convolution are the remaining backlog. Non-Lenia and multi-channel rules run on CPU.

Part V

The verdict

Judged honestly as what it is, not as what would flatter it.

Instrument, not product

As a commercial artifact the direct market is near zero: the audience for a configurable CA engine is small, technical, and served by free tools. As a research and credibility asset in an under-tooled niche, it is worth building. The value is the instrument existing and pointing at a seam nobody else tools well, not anyone paying for it.

Bull case
  • The seam is thin; few are fluent in CA, graphs, and ML together.
  • The analysis layer (graph, detection, and dynamical descriptors on one live state) is genuinely rare.
  • One-config-per-experiment leverage compounds as modules multiply.
Bear case
  • Every individual mechanism already exists; the novelty is integration.
  • Integration is not defensible and is reproducible by any motivated researcher.
  • The moat is taste and follow-through, not technology.

The right framing is internal. AXIOM lowers the cost of a class of experiments its builder actually runs and produces a legible artifact in a niche they own. Judge the next increment by whether it enables a specific experiment, not by a user count that will not exist.

Part VI

Honest limits

Where the current build stops, stated plainly.

The ceiling

  • GPU is unoptimized. Naive global-memory convolution, bandwidth-bound, single-kernel and single-channel only. Multi-kernel, multi-channel, and graph-mode dynamics run on CPU.
  • Sparse work fights the GPU. Graph, particle, and hypergraph substrates run on CPU by design.
  • Learning is gradient-free. Evolution strategies fit local rules well but scale poorly in parameter count; a differentiable backend is the path to morphogenesis-scale NCAs.
  • Loaf is linear. Spacetime relaxation is implemented for diffusion, where the energy is convex. A nonlinear operator makes convergence a real question.
  • The config surface is a north star. The realized surface is the backbone plus a broad vertical slice; the rest is a backlog experiments pull from.
The bottom line

The engine is the contribution, and the individual mechanisms are not novel. The claim is a well-built instrument for an under-tooled seam, with an analysis layer few tools have, validated end to end.
